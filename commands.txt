# Issues Found: Backend is Restarting (Crashing)

Your backend container is in a **restart loop** - it keeps crashing and restarting. This is why the health check fails.

---

## Current Status Analysis

| Container | Status | Problem |
|-----------|--------|---------|
| `mavoid_backend` | ❌ **Restarting** | Crashing repeatedly |
| `mavoid_frontend` | ⚠️ Up (unhealthy) | Can't reach backend |
| `mavoid_postgres` | ✅ Up (healthy) | Working fine |
| `mavoid_postgres_test` | ✅ Up | Working fine |

---

## Step 1: Check Backend Logs to Find the Crash

```bash
# See why backend is crashing
docker-compose logs backend

# Or for continuous monitoring
docker-compose logs -f backend
```

---

## Most Likely Causes (Based on Previous Errors)

### Cause 1: Database Migrations Not Run

The backend cannot connect to a database with tables.

**Fix:**
```bash
# Run migrations
docker-compose exec backend npx prisma migrate deploy
```

### Cause 2: Database Connection Failing

The backend cannot reach PostgreSQL.

**Fix:**
```bash
# Check if database is ready
docker-compose exec postgres pg_isready -U postgres

# Test connection from backend container
docker-compose exec backend node -e "const {Client} = require('pg'); const client = new Client({connectionString: process.env.DATABASE_URL}); client.connect().then(() => console.log('OK')).catch(e => console.log(e.message))"
```

### Cause 3: Missing Environment Variables

Even with defaults, some variable might be missing.

**Fix:**
```bash
# Check environment variables in backend
docker-compose exec backend env | grep -E "JWT_SECRET|DATABASE_URL"
```

## Step 4: If Migrations Fail - Create Initial Migration

If no migrations exist yet:

```bash

docker-compose restart backend
```
